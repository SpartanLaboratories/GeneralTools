Lifecycles and rules

    
How two files make one facade, the two loggers of one name, the rules the code keeps, and what is planned.

    

      
One facade from two files at compile time, on the JVM

        
  1. @file:JvmMultifileClass
  2. @file:JvmName("MiscKt")
  3. both files, same package
  4. one class, MiscKt

        
Both files must keep the two annotations in step, and stay in one module: a facade class cannot span two jars, so the JVM file's functions would land in another class, a binary break. The JVM file's logger and its initialiser live in the part class MiscKt__MiscJvmKt, which is not API.

      
Two loggers, one name com.spartanlabs.generaltools.Misc

        
  1. common: kotlin-logging, TRACE in evaluateList
  2. JVM: slf4j, DEBUG in asURL and read

        
The 2.x name is kept by both, so a consumer's backend rules still match. Each is a file-private val, created on the first call into its file.

      
Rules

        
onException matches the exception's exact class. A subclass of a listed exception is not recovered; an unlisted exception, or one transform throws, stays a failed Result, never thrown.

        
trimIfLongerThan checks the length itself, because substring(0, negative) differs by platform: a negative length throws IndexOutOfBoundsException everywhere.

        
evaluateList iterates once and stops at the first match, calling the validator at most once per item.

      
Planned drawn dashed · its plan

        
  1. the JVM file's logger from kotlin-logging, same name, each call lazy; Logger.time keeps its slf4j receiver
  2. both files in GeneralTools-core, MiscJvm.kt in its JVM source set

Guarantees

  

    
Failure model

      
    
        
  • Thrown, not returned: asURL throws MalformedURLException (declared); read lets the file's I/O exceptions through; trimIfLongerThan throws IndexOutOfBoundsException for a negative length.
    • 
        
  • A caller's lambda that throws propagates unchanged from evaluateList, profile, Logger.time and the forEvery pair.
    • 
        
  • onException returns a Result and never throws. None reports through the failure seam; nothing is retried.
    • 
      

    
Extension points

      
    
        
  • None: closed top-level functions Stable Core; the three JVM ones are JVM only.
    • 
        
  • onException stays public inline, so it cannot log through a file-private logger.
    •

Compatibility & versioning

      
    
        
  • Version 3.0.0, unreleased; Maven Central's latest is 2.2.0. Every public member keeps its place on MiscKt.
    • 
        
  • Breaks: evaluateList takes a Kotlin lambda (descriptor Predicate → Function1); trimIfLongerThan throws the plain IndexOutOfBoundsException; capitalizeEveryWord keeps commas and ignores the default locale.
    • 
        
  • Checked: checkKotlinAbi; the klib dump has no JVM-only function. 3.0.0 is a major with clean breaks, no deprecation cycle.
    • 
      

    
Thread safety

      
    
        
  • The functions keep no state; the only state is the two file-private loggers, each set once.
    • 
        
  • The KDoc states no thread contract. forEvery and forEveryIndexed iterate the caller's collection as forEach does.
    • 
      

    
Resources to close

      
    
        
  • Nothing: read opens the file and Kotlin's readLines closes it before returning; asURL opens no connection.
    • 
      

    
On your classpath

      
    
        
  • org.slf4j:slf4j-api:2.0.16 — api on the JVM, because Logger.time names org.slf4j.Logger in its signature.
    • 
        
  • io.github.oshai:kotlin-logging:8.0.4 — at run time only. Consumed outside the organization: MiscKt's shape changes only in a major.
