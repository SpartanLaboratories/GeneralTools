## 1. Question

With `Point` and `Dimensions` mutable as in 2.x, what does GeneralTools 3.0.0 break in the repositories that consume it, how does the published `gametools` link against it, what changes class by class in this repository, and which lines of `api/GeneralTools.api` change?

Requirements an answer meets, as plain facts about the work:

- The 3.0.0 breaks are exactly: the multiplatform move (Maven-only consumers use `GeneralTools-jvm`); `TwoDoubles` no longer `sealed` (subclassing Experimental through `@SubclassOptInRequired(ExperimentalForInheritanceGeneralToolsApi::class)`); `TwoDoubles.divideBy` returns a `Result` (recommended: divides in place, returns `Result<Unit>`, a failure leaves the value unchanged and logs WARN); `evaluateList` takes `(T) -> Boolean`; `com.spartanlabs.logging` removed; `Square` renamed with `location`/`dimensions` becoming `val`; the equality contract change (NaN equals NaN, `-0.0` hashes like `0.0`, `0.0` still equals `-0.0`); `Color`'s public constructor validates (through `copy` too; `Color.of` still clamps); `trimIfLongerThan` throws `IndexOutOfBoundsException` for a negative length on every platform; the `capitalizeEveryWord` comma fix. Clean breaks, no deprecation cycle.
- Kept as in 2.x: `Point` and `Dimensions` mutable with all in-place members; `Color`'s public constructor and `copy`.
- Added (additive): `ImmutableRectangle` returned by `Rectangle.toImmutable()`; defaulted `minX`/`minY`/`maxX`/`maxY`/`width`/`height` on `AxisAlignedBox`; the opt-in marker. No non-assigning `plus`/`minus`/`times`/`div`.
- Open choices, whose consequences are reported without choosing (section 3.7): what `/=` does on zero; `divideBy` arithmetic; whether `Rectangle.min`/`size` return the live parts or copies.
- Downstream repositories are read and never changed; MyGameTools stays on Kotlin 2.2.0.

## 2. Bottom line

- **The downstream break is one rename plus one assignment.** Across the five repositories, 67 source lines in 22 files stop compiling: 66 are the `Square` rename (MyGameTools 39 lines in 14 files, MyGameClient 27 lines in 8 files) and 1 is `area.dimensions = value` in `VisibleObject.kt:62`, which `val` rejects. MyGameServer, WebTools and SpartanGraphics need no change. The 40 in-place mutation sites in MyGameTools (17 files), its 2 `Color(` calls and MyGameClient's 19 `Color(` calls all keep compiling. No downstream repository has a `divideBy`, `/=`, `evaluateList`, `com.spartanlabs.logging`, exhaustive-`when`-over-`TwoDoubles`, `Color.copy`, `Square.min`/`size` read, `AxisAlignedBox` implementor, or Java source.
- **Every published `gametools` still fails at runtime beside GeneralTools 3.0.0, but now with `NoClassDefFoundError: com/spartanlabs/geometry/Square`**, not `NoSuchMethodError`. Decoded: `Point.setTo`/`plusAssign`, `Dimensions.setWidth`, `Color.<init>` and all other `Point`/`Dimensions`/`TwoDoubles`/`Color`/`CenteredBox` references keep their descriptors and link; only the `Square` class and its members disappear (5 of 31 references in `gametools-core` 5.0.0). The first `new Square` is in `VisibleObject.<init>(Dimensions, Point)` (called by `Actor.<init>`), so any `Actor`/`Alive` construction throws. **`gametools` 5.1.0 is on Maven Central** (uploaded 2026-09-16, requires GeneralTools 2.2.0, adds `gametools-world`, which exists at no other version) with the same verdict.
- **Silent changes (compile, behave differently), downstream:** `VisibleObject.dimensions` setter (instance replaced → values copied, if migrated with `setTo`); `Actor.isAtDestination` (`==`) only when a position is NaN; MyGameClient's `Portrait.color` now throws `IllegalArgumentException` in the render loop for a network-supplied channel outside `0..255`, because nothing on the wire bounds it; MyGameClient's own `Color.lightened` stays shadowed by the GeneralTools member (177 versus 178 in `UiTest`); `toString()` of the renamed type changes its class name. Everything else in the break set has zero downstream sites.
- **MyGameTools migration is small and mechanical:** about 17 files and 45 changed lines (14 files for the rename, 1 for the `val` assignment, the dependency line, README's two diagram lines, a CHANGELOG entry), against about 25 files and 150–200 lines under the immutable model. The issue-#8 gains are limited: `ZoneGrid`'s private origin copy goes; `UnzonedPointException` keeps its copy (`Point` has no immutable twin); retyping `Zone.bounds`/`Space.bounds`/`TiledMap.bounds` to the immutable copy is a source break for MyGameTools' own consumers and removes the premise of 2 tests.
- **Predicted dump ledger (JVM):** 5 classes leave (`Square`, the four `com.spartanlabs.logging` classes: 37 member lines), 3 arrive (`Rectangle`, `ImmutableRectangle`, the marker: 43 member lines); `AxisAlignedBox` +6 and `AxisAlignedBox$DefaultImpls` +6 and `CenteredBox` +6 lines; `TwoDoubles` loses 2 synthetic constructors and `divideBy (D)V`, gains `divideBy-IoAF18A (D)Ljava/lang/Object;` (hash computed, section 3.5) and three constructor lines, and `equals`/`hashCode` gain `final`; `CenteredBoxKt` 2 lines and `MiscKt.evaluateList` 1 line change descriptor. `Point`, `Dimensions`, `Segment`, `Ray`, `Color`, `IntersectionsKt`, `VectorsKt`, `UserActionsKt` show no change. The dump cannot show unsealing, the opt-in gate, equality, `divideBy`'s WARN and in-place semantics, `Color` validation, `trimIfLongerThan`, `capitalizeEveryWord`, or the `/=` and `min`/`size` choices; section 3.6 names the check for each.

### 3.2 Silent changes (compile, behave differently) (reasoned from the sites above)

- **S1. `VisibleObject.dimensions` setter.** 2.x stores the caller's `Dimensions` instance as `area.dimensions` (`obj.dimensions = d; d.width = 9.0` resizes `obj`; the previous instance is detached). `area.dimensions.setTo(value)` copies `d`'s values into the existing instance: later changes to `d` no longer reach `obj`, and a holder of the old `area.dimensions` now sees the update. `area` is a `val` constructor property, so `area = Rectangle(location, value)` is not available as an alternative. No downstream caller of the setter exists (grep: none).
- **S2. NaN equality.** `Actor.isAtDestination` compares `Point`s with `==`. In 2.x `TwoDoubles.equals` has no identity shortcut and compares with IEEE `==`, so a position with a NaN coordinate is unequal even to itself; with the equality contract change it is equal. Reachable where `location` and `destination` are NaN together; `Alive.kt:126` (`destination = location`) and `:207` (`destination = attackTarget!!.location`) make them the same object (the aliasing is unchanged under the mutable model). `0.0` versus `-0.0` is unchanged: still equal.
- **S3. `toString()`.** The renamed data class prints its new name (`Rectangle(location=…, dimensions=…)`); `Zone`'s generated `toString` embeds it. No downstream test asserts on it (grep: none).
- **S4. `Portrait.color`** (section 3.1): an out-of-range snapshot channel moves from "stored" to "exception in the frame loop".
- **S5. Published `gametools` binaries** (section 3.3): not a source change; a runtime failure.
- Not downstream-visible: the kotlin-logging startup line on first use (a consumer-wide stdout line, [`kotlin-logging-adoption.md`](kotlin-logging-adoption.md)), WARN instead of ERROR, `capitalizeEveryWord`, `trimIfLongerThan` (JVM: `substring` already throws `StringIndexOutOfBoundsException`, a subtype of `IndexOutOfBoundsException`; only a handler naming the subtype would notice), `Color.fromHex` with a signed digit pair (`"#-1-1-1"` parsed to a `-1` channel in 2.x, now throws `IllegalArgumentException`).

It is a runtime error, not a compile error, and appears only when one of those constructors runs. The class verifier may report it earlier at class linking; which of the two happens first was not established. The mutable model moves the failure from the immutable model's `NoSuchMethodError` (`Point.setTo`/`plusAssign` removed) to this one, and shrinks the failing surface: `Point`-based code such as `gametools-net`'s command applier links. State in the release notes that no published `gametools` can run beside GeneralTools 3.0.0, and that MyGameTools consumers should not add GeneralTools 3.0.0 directly until a MyGameTools release built on it exists.

## 4. How comparable projects do it

- **Sizing and documenting a rename-plus-behaviour major.** Okio 3.0.0 opens with who is affected ("Most users should be able to upgrade from 2.x by just changing the version"), lists one bullet per change and labels the one binary break explicitly; the Ktor 2→3 guide gives a rename table, an old/new code pair or numbered steps per change; kotlinx-datetime 0.8.0 groups "Breaking changes", "Additions" and "Tweaks and fixes" ([`idiomatic-kotlin-api-mechanics.md`](idiomatic-kotlin-api-mechanics.md) F8, with links). The pattern fits here with known consumers: a count per category for the two affected repositories, the symptom-to-fix index above, and a separate list for the changes that compile (section 3.2).
- **A binary-incompatible major beside its consumers.** Apache Commons Lang 3.0 changed its package name and states the reason: "we have changed the package name, allowing Lang 3.0 to sit side-by-side with your previous version of Lang" (claim 2). GeneralTools keeps its coordinates and package names, so a consumer library compiled against 2.x cannot coexist with 3.x in one resolution; Gradle selects the highest version (claim 1). Section 3.3 is the measured form of that hazard.
- **A deprecated alias for a rename.** The Kotlin way to keep a renamed type compiling is a `typealias`, which "doesn't create a new type" (claim 5); it leaves no class in the JVM bytecode, so it would make the 41 MyGameTools and 29 MyGameClient lines compile with a warning but not the published binaries. It is also a deprecation cycle, which the 3.0.0 break set excludes.
- **Mutable rectangle beside an immutable one.** Compose `MutableRect.toRect()`, korlibs' deprecated `MRectangle` and AWT's copy-on-`getBounds()` are in [`mutable-geometry-model.md`](mutable-geometry-model.md) §4; none of them is a downstream-sizing precedent.

## 5. Pitfalls and regrets

1. **A rename is a source fix and a binary break.** One search-and-replace repairs 66 lines, and every published `gametools` still fails at its first `new Square`. A `typealias` does not help the binaries (section 4).
2. **`area.dimensions = value` has two plausible migrations and they differ.** `area.dimensions.setTo(value)` copies values (S1); `area = Rectangle(…)` is impossible because `area` is a `val`. The notes must show the first and say it copies.
3. **`divAssign` with an expression body silently picks up the new return type.** It becomes `Result<Unit>` and fails the operator check, which is useful (it is a compile error), but only if the body is not also changed to hide it.
4. **Validation moves a bad value's failure from storage to use.** The wire never carried a bound; MyGameClient's `Portrait` is the one site where a bad snapshot now ends the client. Fix on the client with `Color.of`; on the server the validated `Color` prevents it.
5. **The dump decides on constructor visibility.** `TwoDoubles` is `abstract` with public constructors by default, which adds `<init> ()V`, `<init> (DD)V` and `<init> (TwoDoubles)V` to the baseline; `protected` changes three lines and the intent. Choose before the checkpoint dump is committed.
6. **New defaulted members on an interface are a source risk for external implementors.** A Kotlin class that implements `AxisAlignedBox` and already declares `width` or `minX` with another type fails to compile. None exists in the five repositories; unknown consumers are the residual (the reason it ships in a major).
7. **Renaming the wrong file renames a facade.** `Square.kt` holds only the class, so its rename is neutral to the dump; `CenteredBox.kt` holds `CenteredBoxKt` and must keep its name though `toSquare` becomes `toRectangle`.
8. **The README's downstream note is stale.** It says MyGameTools' last published release is `gametools` 5.0.0 with GeneralTools 2.0.1. Central also has 5.1.0 (GeneralTools 2.2.0, with `gametools-world`), and the git tag `v5.1.0` does not match the published bytes (section 3.3).
9. **Tests that name the old type.** Backtick test names containing "Square" survive a rename as stale text and cannot be found by a symbol search.

In this repository: the verdict table in 3.5, 4 test files touched by the rename, 2 tests that change by design (`SquareTest` reassignment test, `ColorTest` constructor test), new tests per 3.6.
